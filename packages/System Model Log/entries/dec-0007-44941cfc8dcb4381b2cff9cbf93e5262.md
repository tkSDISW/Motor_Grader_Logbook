## Decision: PA Layer Stays Flat — No L5 Hierarchy Mirrored from LA/Essential

### Context
Starting PA/Incarnation layer work using the L3/L4 reference image (Engines, Cooling, Drivetrain, Hydraulics, Electrical, Operator Environment, Undercarriage, Structures, Enclosures) as a content guide.

### Decision
The PA layer will **not** mirror the 7-grouping L5/Essential hierarchy built at LA (`Power Management`, `Machine Motion Control`, `Grade & Work Tool Management`, etc.). `Motor Grader` at PA stays a **flat boundary** — physical components (Engine, Transmission, Hydraulics, Controller, Bus, etc.) sit directly under it, not nested under L5-named parents.

### Rationale
Several physical components are genuinely cross-cutting and would require duplication or false single-ownership if forced into the LA hierarchy. The clearest example: **Hydraulics** serves `Power Management` (as source), and both `Machine Motion Control` and `Grade & Work Tool Management` (as consumers) — it cannot honestly have one L5 parent without misrepresenting the physical reality. Capella's strict single-parent containment tree would force an arbitrary choice if the hierarchy were mirrored.

### Approach going forward
- **Containment** at PA answers "what's physically inside the machine" — flat under `Motor Grader`.
- **Diagram names** (`[PAB] <category>`, e.g. `[PAB] Hydraulics`, `[PAB] Engine`) carry the physical category, not the L5 relationship — kept simple even for cross-cutting components, rather than cramming multiple L5 names into a diagram title.
- **Realization links** (LA component realized-by PA component) are the actual mechanism for capturing which L5/Essential grouping(s) each physical component serves — including many-to-many cases like Hydraulics serving three L5 groupings. User will create these links directly in Capella Studio.
- These realization links can later be pulled via `capella-fabric`'s fabric generation to produce a report showing the cross-cutting physical systems and everything they realize — a traceability view that a naming convention alone couldn't cleanly express.

### PA state at time of this decision
Already built by user: `Motor Grader` (flat, uuid `03299678-39f7-49ae-a214-ea50048a921a`) containing `Engine`, `Transmission`, `Controller`, `Bus`. Proposed remaining gaps to fill (from the L4 reference): `Cooling`, `Hydraulics`, `Electrical`, `Operator Environment`, `Undercarriage`, `Structures`, `Enclosures` — plus a note that `Structures` likely needs no L5 realize link at all, consistent with the earlier `Super Structure` conclusion (`dec-0006`/discussion) that pure chassis/structural content has no Essential-layer behavior to abstract.
