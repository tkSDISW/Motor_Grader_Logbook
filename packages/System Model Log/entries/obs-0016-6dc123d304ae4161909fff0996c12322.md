## PMEI Correction (Grader Operator Physical Controls) + Status Channel Network Named

### User correction: Grader Operator exchanges reclassified I → P
User correctly flagged that the exchanges originating from `Grader Operator` (steering wheel, shift levers, blade control levers) represent literal physical/mechanical control interfaces, not information — the operator's hand-to-control interaction is a physical mating, even though the downstream signal is eventually digitized. Reclassified 6 exchanges from `[I]` to `[P]`:

- `[P] Steering Control` (SA, uuid `a996c459-7087-4c19-ba6f-cfec1f04e52e`)
- `[P] Blade Position Control` (SA, uuid `d7d1ec12-5329-49fb-a326-a0553171c1d7`)
- `[P] Direction Control` (SA, uuid `302dc048-1f8f-43ac-b5cd-63faf37d895d`)
- `[P] Steering Control` (LA, uuid `54a7a479-ef67-4501-bdad-4fff172ed8ae`)
- `[P] Blade Position Control` (LA, uuid `5ca1b4ce-fdb8-4034-acd1-c39ed5355f45`)
- `[P] Direction Control` (LA, uuid `6b272e34-abfa-4b96-8b3e-f4d1827b64ab`)

This refines the PMEI convention established in `dec-0003`: the classification should reflect the physical nature of the human-machine interface itself where applicable, not just the abstract "it's a command" framing. Everything downstream of the physical control (e.g. `Steering Command Channel`, `Blade Command Channel`) remains `[I]` since those genuinely are digitized/electronic signals between subsystems.
