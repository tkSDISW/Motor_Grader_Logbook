## Decision: Rework LA Layer as Essential (Logical) with Current Components Reframed Toward Incarnation (Physical)

### Context
Following `dec-0005` (adoption of McMenamin & Palmer's Essential/Incarnation terminology for LA/PA), a review of a reference system-complexity hierarchy image (L3 Simple Systems → L4 Complex Systems → L5 Multiple Integrated Systems) surfaced an important observation: the L4/L3 names in that reference (`Engines`, `Hydraulics`, `Drivetrain`, `Fuel System`, etc.) are technology-committed — Incarnation-flavored — while the L5 names (`Power Management`, `Auto-Dig`, `Machine Control`, `Information Solutions`, `Operator Interface`) are technology-independent — genuinely Essential.

Applying this lens to our own LA layer revealed that our current 12 logical components (`Hydraulic System`, `Engine and Powertrain System`, `Steering System`, `Blade System`, etc.) are themselves already Incarnation-flavored, not Essential — they presume specific technology (hydraulic actuation, IC engine, etc.) rather than describing pure required behavior independent of implementation.

### Decision
Rework the LA layer: treat the current 12 components as candidates for the future PA/Incarnation layer, and build a genuinely Essential/logical LA above them by consolidating related technology-committed components into technology-independent groupings, named in the spirit of the L5 reference:

| Current (Incarnation-flavored) components | → Proposed Essential grouping |
|---|---|
| Engine and Powertrain System, Hydraulic System | Power Management |
| Steering System, Steering Control Subsystem, Direction Control System | Machine Motion Control |
| Blade System, Grade Control System | Grade & Work Tool Management |
| Attachment Subsystem | Variable Accessory Management |
| Telematics Module, Super Structure | Information Solutions |
| Operator Cabin | Operator Interface System |
| Service Interface | Service & Support Management |

This takes the LA layer from 12 flat components down to 7 Essential groupings, closely matching the L5 reference's own granularity (a useful consistency check on the approach).

### Rationale
At the Essential level, it should not matter *how* a function is realized (hydraulic vs. electric actuation, diesel vs. alternative power) — only *what* the system must do. The current component set encodes those "how" decisions directly into LA structure, which is a common and easy drift in real projects (this is precisely the failure mode McMenamin & Palmer's Essential/Incarnation distinction was designed to prevent).

### Scope of this pass
This entry logs the decision and naming only. Per the user's direction, the actual structural rework (how the 7 new Essential-level components relate to the 12 existing ones — merge, re-parent, or treat as separate future-PA seed) is deliberately deferred. This session will only add the 7 new components as new top-level structural elements; the user will handle reworking structure and diagrams to relate them to the existing 12 components in Capella Studio.
