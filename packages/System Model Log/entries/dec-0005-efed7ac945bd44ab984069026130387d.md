## Decision: Adopt "Essential / Incarnation" Terminology (McMenamin & Palmer) for LA/PA; P-Diagrams Centered on Node Components

### Context
Stephen M. McMenamin and John F. Palmer are foundational figures in systems analysis, known for authoring the 1984 book *Essential Systems Analysis*. That work distinguishes between the **Essential Model** (the technology-independent logical view of what a system must do) and its **Incarnation** (the technology-bound physical implementation of that essential model).

### Decision
Going forward, this project will map that terminology onto the existing Capella layers:
- **Logical Architecture (LA) stays "Essential"** — the technology-independent model of the system's required behavior and structure.
- **Physical Architecture (PA) will be referred to as "Incarnation"** — the concrete, technology-bound realization of the Essential model.

### Consequence: Physical environment factors reflected on node component diagrams
Because the Incarnation layer is where technology and environment actually bind to the design, **physical environment factors will be reflected on the Physical (PA) Node Component diagrams.**

To support this, **P-Diagrams (Parameter Diagrams, from robust/reliability engineering) will use Node Components as their central element** — the standard P-Diagram structure (Signal → Control Factors → System/Process → Noise Factors → Response) will be organized around each Node Component as the "system" block. **Noise factors will be shown explicitly on the node diagrams**, rather than left implicit, so that environmental and uncontrollable-factor exposure is visible directly on the physical architecture rather than only in a separate analysis artifact.

### Rationale
This grounds the LA→PA transition in a well-established, citable systems-engineering vocabulary (McMenamin & Palmer, 1984) rather than inventing new terminology, and it gives the physical/Incarnation layer a concrete home for environmental/robustness considerations (noise factors) that don't have a natural place in the Essential (LA) model, since those factors are technology- and environment-dependent by definition.

### Next steps
Not yet started: building out the PA/"Incarnation" layer itself, or the P-Diagram structure on the Node Component diagrams. To be picked up in a future session.
