## Refinement to dec-0007: PA Diagrams Named by L5/Essential Grouping, Not Just Physical Category

### Context
Following `dec-0007` (PA stays flat, no mirrored L5 hierarchy), reconsidered how the L5 relationship should be captured. Rather than plain physical-category diagram names (`[PAB] Hydraulics`) with the L5 mapping left entirely to realization links, the user prefers diagrams named directly after the L5/Essential grouping they represent.

### Decision
PA diagrams will be organized **one per L5 Essential grouping**, not one per flat physical category. Each diagram shows whichever flat PA components participate in realizing that grouping — a component like `Hydraulics` can legitimately appear on multiple diagrams (e.g. both `Machine Motion Control` and `Grade & Work Tool Management`), since diagrams are views, not ownership. Containment stays flat under `Motor Grader` exactly as decided in `dec-0007` — only the diagramming/naming approach changes.

### Proposed diagram set
| Diagram | Physical content shown |
|---|---|
| `[PAB] Power Management` | Engine, Transmission, Cooling, Hydraulics (source), Electrical |
| `[PAB] Machine Motion Control` | Hydraulics (consumer), Controller, Undercarriage, Bus |
| `[PAB] Grade & Work Tool Management` | Hydraulics (consumer), Controller, Bus |
| `[PAB] Variable Accessory Management` | Hydraulics (consumer), Controller |
| `[PAB] Information Solutions` | Bus, Controller |
| `[PAB] Operator Interface System` | Operator Environment, Enclosures (cab shell), Controller (HMI/display) |
| `[PAB] Service and Support Management` | Enclosures (access panels), Electrical (service points) |

**Deliberate exception:** `Structures` (frame/chassis) gets its own plain `[PAB] Structures` diagram with no L5 name — consistent with the earlier `Super Structure` conclusion that pure structural content has no Essential-layer behavior to realize.
