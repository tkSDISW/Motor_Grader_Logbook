**Actors and entities in OA: changing between them changes the element's UUID. Flag for the Member Handbook (for Cousin to review).**

In the jobsite model, the two actors (Regional Regulator, Road Authority/Client) were first created by patch as OA entities with `is_actor: true`. In Capella, the engineer recreated them as actors, because actors and entities are different element types there. The result: both elements got **new UUIDs** (`efd9bfa2-...`, `22ca4fdc-...`; the old ones were `648bba51-...`, `badb1032-...`), and any UUIDs logged earlier for them went stale.

**Why it matters:** the Handbook's `mcp_tools` note "capella-fabric: Reading and Changing a Model Safely" says an actor is not a separate kind of element but a component/entity flagged `is_actor`. That holds for how capella-fabric reports elements, but the engineer's experience is that, in Capella, actor vs. entity is a type choice, and switching means recreating the element with a new UUID.

**Practice:**
- Decide actor vs. entity before creating the element, and ask the engineer when unsure.
- Don't carry UUIDs across a type change; re-browse after pulling.
- Log elements by name plus UUID, and note when a UUID goes stale.

**Suggested handbook action (for Cousin, engineer's request):** add a note to the "Telling actors from components" section about type changes producing new UUIDs. This is a hypothesis from one session; verify before editing the Handbook.
