## The "C10" Saga — Empty Connection to Fully Named Attachment Actuation Path

### Timeline
1. **Discovered empty**: During the wheel/traction naming pass, `C10` (a ComponentExchange between Blade System and Attachment Subsystem) was found with no allocated functional exchange — flagged as an open item rather than guessing a name blind.
2. **First attempt**: User reported resolving it by creating a new functional exchange, but investigation showed the new exchange (`FunctionalExchange 48`, connecting `Determine Blade Adjustment` on Grade Control System to `Deliver Attachment Capability` on Attachment Subsystem) didn't match C10's actual endpoints (which were still Blade System → Attachment Subsystem) — a real component mismatch, not just a naming gap.
3. **Endpoints fixed**: User rerouted `C10`'s source endpoint from Blade System to Grade Control System, matching the same Grade Control System → Attachment Subsystem pattern already used for the Blade actuation path (`Moldboard Actuation Channel`). Confirmed via direct XML parent inspection of both ports.
4. **Allocation gap**: Endpoints matched, but `FunctionalExchange 48` still wasn't allocated onto `C10` — a separate step in Capella Studio from fixing endpoints. First push didn't include it.
5. **Allocation confirmed**: User re-pushed (commit `47f876a`, message "Committed allocation of C10") and the allocation was confirmed present.

### Final naming (commit `d06f9b99`, model repo `https://github.com/tkSDISW/Motor_Grader/`, branch `master`)
- `FunctionalExchange 48` → `Attachment Actuation Command`
- `C10` → `Attachment Actuation Channel`

Both names mirror the existing `Moldboard Actuation Command` / `Moldboard Actuation Channel` pattern for consistency.

`verify_model` on LA: 0 findings throughout.

### Takeaway for future troubleshooting
Component exchange endpoint mismatches and missing functional-exchange allocations can look identical from the outside (an "empty" or seemingly broken connection) but require different fixes — endpoints must match at the component level before an allocation is even possible, and allocation is a distinct action from endpoint routing. Worth checking both explicitly when a connection looks unresolved.
