## Scope Statement — Why This Package Exists

**Date:** 2026-09-02

**This package curates requirements that complement the motor grader Capella model being built alongside it in this same log book** — capturing what the system needs to do as it's discovered during modeling, in a lightweight, pre-formal form, before (and independent of) any commitment to a specific downstream requirements tool.

**This is the same real exploration already underway in `requirements`/note-0002 in `knowledge_partner`, now given a second, live test case.** The concern that motivated the original package still applies here directly: an engineering tool's own MCP risks becoming a thin, bypassable wrapper if it only offers CRUD operations rather than genuine domain logic — the schema itself (the Constraint distinction, a real verification method per requirement, explicit rationale and source) is what keeps a curated requirement meaningfully structured, not just a stored string.

**This repo is also the live test case for `candidate_playbooks`/OBS-0016's own portable-requirement-curation playbook** — the goal is a requirement set that stays Capella-compatible from the start, while remaining readily importable into Polarion or Teamcenter Requirements if and when this model's requirements need to flow into either. It's also a real instance of OBS-0016's own teaching/content angle — a requirement set built without needing to first pick or license a commercial requirements tool.

**Reference:** `requirements`/note-0002 in `knowledge_partner` (the original scope statement this mirrors), `candidate_playbooks`/OBS-0016 in `knowledge_partner` (the playbook this repo tests live).
